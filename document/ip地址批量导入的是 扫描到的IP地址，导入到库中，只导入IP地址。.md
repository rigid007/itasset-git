
1、ip地址批量导入的是 扫描到的IP地址，导入到库中，只导入IP地址。

2、根据协议返现的拓扑，“网络拓扑发现”时，也可以按照协snmp、lldp 协议发现 不支持LLDP ，并且也入库，设备可能携带MAC信息。

3、根据协议返现的拓扑， “ip/mac发现”是，按照交换机的arp表及mac地址表，补齐已经入库有ip地址的补MAC，有MAC的可以补IP.


以上三种方式找设备入库，有可能发现的同一设备，没有统一的补齐信息，而三次入库。


现在问题是：

1、有没有一种有效的办法，把不支持snmp、lldp的设备连在交换机上，发现与交换机连接的拓扑、

2、如果没有，上面的三种方法，如何相互补齐，尽量保证1个设备仅入库1次。



=======================================


问题	解决方案
三种发现方式各自独立入库	统一使用 find_or_create_device 服务，按 IP→MAC→名称 顺序查重
不支持LLDP的设备无法发现拓扑	通过 IP/MAC 发现（ARP表+MAC表）可以发现终端设备与交换机的连接
同一设备被多次创建	发现任务完成后自动调用 merge_devices_by_ip_mac() 合并重复设备
信息不完整	合并时自动补充 IP、MAC、名称、类型等信息



使用建议

    先执行 IP/MAC 发现：获取 ARP 表和 MAC 表，建立设备与端口的关联

    再执行协议发现：通过 LLDP/SNMP 发现设备间连接

    最后执行 IP段导入：补充只有 IP 的设备

    每次发现后自动合并：确保同一设备只保留一条记录
