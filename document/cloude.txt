 整体思路

 按照 按模块逐步交付 方式，依次优化5大模块。每个模块独立完成（模型 → 路由 → UI），确保可独立验证。各模块之间存在依赖关系的，后置模块会复用前置模块的成果。

                                                                                                                                                                                                     按照 按模块逐步交付 方式，依次优化5大模块。每个模块独立完成（模型 → 路由 → UI），确保可独立验证。各模块之间存在依赖关系的，后置模块会复用前置模块的成果。

     执行顺序：
     1. 资产管理（核心基础）
     2. 配置管理（可并行或先期完成，为其他模块提供基础能力）
     3. 监控（依赖资产和配置）
     4. 运维管理（依赖监控告警数据）
     5. 综合报表（依赖所有模块数据）

     ---
     模块一：资产管理优化

     目标

     补齐企业级 ITAM 的行业标准能力：生命周期管理、合同管理、软件许可、TCO成本追踪、资产盘点、通知提醒。

     新增模型

     1.1 Contract 合同管理模型 (models/contract_models.py)

     Contract:
       - id, contract_no(唯一), name, type(purchase/maintenance/lease/sla)
       - supplier_id -> suppliers.id
       - start_date, end_date, renewal_date
       - total_value, payment_terms, payment_status
       - attachment_url, description
       - status(active/expired/termined/renewed)
       - notification_days(到期提前提醒天数)
       - created_at, updated_at
       - assets relationship (多对多, contract_assets关联表)

     1.2 SoftwareLicense 软件许可模型 (models/license_models.py)

     SoftwareLicense:
       - id, license_key, software_name, version, edition
       - license_type(per_user/per_device/enterprise)
       - vendor, publisher
       - total_quantity, allocated_quantity, available_quantity
       - purchase_date, expiry_date, renewal_date
       - purchase_cost, unit_cost
       - contract_id -> contracts.id(optional)
       - status(active/expired/deprecated)
       - compliance_status(compliant/non-compliant/under-review)
       - created_at, updated_at
       - devices relationship (多对多)

     1.3 AssetAudit 资产盘点模型 (models/audit_models.py)

     AssetAudit:
       - id, audit_no(唯一), name
       - audit_type(annual/quarterly/random)
       - status(draft/in_progress/completed/cancelled)
       - scope_location_ids, scope_department
       - scheduled_date, completed_date
       - total_assets, scanned_assets, matched_count, discrepancy_count
       - missing_count, damaged_count
       - notes
       - created_by -> users.id
       - created_at, updated_at

     AssetAuditItem:
       - id, audit_id -> asset_audits.id
       - asset_id -> assets.id
       - expected_location, actual_location
       - expected_status, actual_status
       - scanned_by, scanned_at
       - status(matched/mismatched/missing/extra)
       - notes
