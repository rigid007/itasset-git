数据库版本不一致 的问题，我给你一套最安全、直接可用的修复方案，一步步照着执行就行。
一步一步修复（直接复制命令）
1. 先回退 migrations 版本（跳过已存在的表）
bash
运行

flask db downgrade

2. 强制标记当前数据库为最新版本（解决 not up to date）
bash
运行

flask db stamp head

3. 现在重新生成迁移文件（你要加 cabinet 字段）
bash
运行

flask db migrate -m "add cabinet fields"

4. 最后执行更新
bash
运行

flask db upgrade

为什么会报错？
 

    Target database is not up to date你的 migrations 记录和数据库实际版本不一致。flask db stamp head 就是强制对齐。
    Table 'report_executions' already exists之前的迁移脚本尝试创建一个已经存在的表，所以报错。回退版本后重新生成，就不会重复创建了。

如果你还是报错（终极安全方案）
如果上面步骤还失败，直接清理冲突的迁移版本：

    打开项目里的 migrations/versions/ 文件夹
    删除 里面以 948287cceb15_ 开头的那个文件（就是报错的文件）
    再执行：

bash
运行

flask db stamp head
flask db migrate -m "add cabinet fields"
flask db upgrade



==============增加一个字段，如何迁移数据库？ ==========================

class Device(db.Model):
    # ... 现有字段 ...
    mac_address = db.Column(db.String(17), nullable=True)  # 存储设备 MAc
要为 Device模型添加 mac_address字段并进行数据库迁移，这里提供两种主流方案：
方案一：使用 Flask-Migrate/Alembic（推荐）
1. 安装 Flask-Migrate

pip install Flask-Migrate

2. 初始化迁移环境

# 在应用初始化代码中添加
from flask_migrate import Migrate

migrate = Migrate(app, db)

3. 生成迁移脚本

# 初始化迁移目录（只需第一次运行）
flask db init

# 生成迁移脚本
flask db migrate -m "Add mac_address field to Device table"

4. 检查并应用迁移

# 检查生成的迁移脚本是否正确
# 查看 migrations/versions/ 下的文件

# 应用迁移
flask db upgrade
