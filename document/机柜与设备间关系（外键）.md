1. 修正模型定义
删除 Cabinet 模型中的错误行
python

# 错误：这行应删除
cabinet_id = db.Column(db.Integer, db.ForeignKey('cabinets.id', ondelete='CASCADE'))

修改 Device 模型的外键
python

cabinet_id = db.Column(db.Integer, db.ForeignKey('cabinets.id', ondelete='CASCADE'))

同时，确保 Cabinet 模型中存在关系：
python

devices = db.relationship('Device', backref='cabinet')

2. 生成并执行迁移
bash

flask db migrate -m "Set cascade delete for cabinet devices"
flask db upgrade

如果之前已经存在该外键，迁移脚本可能只是修改约束。如果遇到迁移问题，可能需要手动编辑迁移脚本（添加 ondelete='CASCADE' 到外键定义）。
3. 调整删除路由逻辑

由于现在启用了数据库级联删除，删除机柜时会自动删除其下的所有设备。因此您的路由中不应再返回 400 阻止删除，否则用户无法删除有设备的机柜。
修改后的删除路由
python

@app_bp.route('/cabinets/<int:id>/delete', methods=['POST'])
@login_required
def cabinet_delete(id):
    cabinet = Cabinet.query.get_or_404(id)
    
    try:
        # 可选：提示用户将删除多少设备
        device_count = cabinet.device_count
        if device_count > 0:
            # 如果希望提示用户，可以返回确认信息，但这里直接删除（级联）
            pass  # 或者记录日志
        
        cabinet_name = cabinet.name
        db.session.delete(cabinet)
        db.session.commit()
        
        return jsonify({
            'success': True,
            'message': f'机柜 "{cabinet_name}" 及其关联的 {device_count} 个设备已删除'
        })
        
    except Exception as e:
        db.session.rollback()
        return jsonify({
            'success': False,
            'message': f'删除失败: {str(e)}'
        }), 500

如果您希望保留前端提示（“机柜下有设备，是否确认删除？”），可以在前端增加确认步骤，后端则直接删除。
4. 确认外键约束已启用

    SQLite：默认关闭外键约束。需要在创建引擎时开启：
    python

    engine = create_engine('sqlite:///your.db', connect_args={'foreign_keys': 'ON'})

    PostgreSQL / MySQL：默认开启，无需额外配置。

5. 验证修改

重启 Flask 应用，再次尝试删除机柜。如果仍然返回 400，请检查后端控制台输出的具体错误信息（可能是其他业务逻辑返回的 400）。
常见问题排查

    为什么出现 400 错误？
    很可能是您当前的删除路由中仍有 if cabinet.device_count > 0: return jsonify(...), 400 的检查。请确认路由代码中已移除该检查或改为允许删除。

    数据库迁移失败？
    如果修改外键约束时报错（如 SQLite 不支持修改外键），可考虑：

        手动删除现有外键，再添加新外键。

        或备份数据后重建表。

    关系未定义？
    如果 cabinet.devices 未定义，请确认 Cabinet 模型中已添加 devices = db.relationship('Device', backref='cabinet')。

按照以上步骤修正后，删除机柜时即可自动级联删除其下的设备，不再出现 400 错误。
