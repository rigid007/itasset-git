# 服务器（宿主机）与交换机连接发现 — 落地方案与系统能力说明

## 背景

核心交换机 + 服务器汇聚交换机的场景下，若用 IP/MAC 模式搜索服务器，虚拟化宿主机上行口上
会学到大量虚拟机网卡 MAC，旧的判定规则“端口 MAC ≥ 2 即级联”会把宿主机误判成级联交换机，
导致服务器与交换机的物理连接关系丢失或画错。

正确思路：物理连接关系以 **LLDP/CDP 邻居表为准**，MAC 表只做兜底；宿主机识别靠
“VM OUI 过滤 + 端口 MAC 组成 + LLDP 能力位”组合判定。

## 四步落地清单与本系统支持情况

| 步骤 | 内容 | 系统支持情况 |
| --- | --- | --- |
| 1 | 交换机全局开启 LLDP/CDP，SNMP 读取 `lldpRemTable` 建立物理拓扑骨架 | 已支持：`discover_lldp_neighbors()` 读取 LLDP-MIB（本地端口描述、ifIndex 映射、远端 chassis/port/sysname/sysdesc/能力位），`get_lldp_management_addresses()` 读取 lldpRemManAddr；CDP 通过 CISCO-CDP-MIB 读取；多轮 BFS 多级发现 + LLDP 链路老化标记 |
| 2 | 宿主机侧按平台开启 LLDP（vDS / lldpd / NetLldpAgent） | 系统侧已支持识别并记录宿主机（LLDP 能力位 + sysDesc 关键字）；宿主机开启 LLDP 为运维动作，见下方操作指引 |
| 3 | 两端交叉核对：交换机端口 ↔ 宿主机物理网卡 MAC ↔ BMC MAC ↔ 管理 IP | 新增：Device 增加 `bmc_ip`/`bmc_mac`/`virtualization_type`/`is_virtual_host` 字段；新增“拓扑管理 → 服务器连接核对”报表页（含 CSV 导出） |
| 4 | 对未开 LLDP 的老机器用 OUI 过滤 + 端口特征兜底 | 已支持：`utils/vm_oui.py` 按 VM OUI 识别宿主机口，只取物理网卡 MAC 建链；真级联口（多非虚拟化 MAC）仍按级联跳过 |

## 一、交换机侧（LLDP/CDP + SNMP）

华为（VRP）示例：

```text
system-view
lldp enable
snmp-agent mib-view included LLDPView 1.0.8802
snmp-agent community read <community> mib-view LLDPView
save
```

> 注意：华为设备即使开了 `lldp enable`，SNMP 默认也不暴露 LLDP-MIB，必须把 `1.0.8802`
> 加入 community 的 MIB 视图，否则网管读 `1.0.8802.1.1.2.1.4.1.1` 会返回 No Such Object。

H3C：`lldp enable`；思科：`lldp run`（或 CDP：`cdp run`）。

网管侧读取 `1.0.8802.1.1.2.1.4.1.1.*`（lldpRemTable）与 `1.0.8802.1.1.2.1.4.2.1.1`
（lldpRemManAddr，对端管理 IP），即可把交换机端口与宿主机 IP 对上。

## 二、宿主机侧开启 LLDP（运维动作）

| 平台 | 开启方式 |
| --- | --- |
| VMware ESXi（vDS） | vCenter 中在分布式交换机“网络发现”里开启 LLDP（发送+接收）；vSphere Client 或 `esxcli network vswitch dvs lldp set` |
| VMware ESXi（vSS） | 标准交换机不支持 LLDP，仅 Cisco 的 CDP 可用（`esxcli network vswitch standard set --cdp-status both`）；建议使用 vDS |
| KVM / Proxmox | `apt install lldpd && systemctl enable --now lldpd`，确认上行网卡启用；`lldpcli show neighbors` 验证能看到对端交换机 |
| Hyper-V / Windows Server | 宿主机物理网卡启用“Microsoft LLDP Protocol Driver”，PowerShell：`Enable-NetLldpAgent -NetAdapterName <网卡>` |
| 无 LLDP 的老机器 | 至少保持 SNMP 可读 MAC 表/ARP 表，由本系统 OUI 兜底识别 |

## 三、系统新增能力

### 1. 宿主机识别工具 `utils/vm_oui.py`

- VM OUI 表：VMware（00:50:56 / 00:0C:29 / 00:05:69 / 05:00:56）、Hyper-V（00:15:5D）、
  Xen（00:16:3E）、KVM/QEMU（52:54:00）、VirtualBox（08:00:27）、Parallels（00:1C:42）。
- 端口分类：单 MAC=终端直连；多 MAC 含 VM OUI=虚拟化宿主机上行口；
  多 MAC 无 VM OUI=交换机级联/上行口。
- LLDP 能力位分类：macBridge→交换机，router→路由器，station→服务器/主机。
- sysDesc/sysName 关键字识别平台：vmware/hyperv/kvm/proxmox/xen/virtualbox/parallels。

### 2. 发现逻辑改造（`blueprints/topology.py`）

- `discover_neighbors_via_snmp_mac()`：不再整口跳过宿主机上行口，只取物理网卡 MAC 建链，
  并把 `neighbor_type=hypervisor`、`vm_mac_count`、`hypervisor_platform` 写入连接记录。
- `run_ipmac_discovery()`：核心/接入交换机的端口按上述分类处理，VM MAC 不参与建链，
  宿主机物理网卡 MAC 正常建链并标记。
- `save_discovery_results()` / `save_ipmac_results()`：识别到宿主机证据时自动把目标设备
  标记为 `is_virtual_host=True` 并写入 `virtualization_type`。

### 3. 数据库变更（迁移）

新增迁移：`migrations/versions/l3m4n5o6p7q8_add_server_link_verify_fields.py`

```bash
flask db upgrade
```

新增字段：

- `devices.bmc_ip` / `devices.bmc_mac`：服务器带外管理（BMC）信息；
- `devices.virtualization_type`：虚拟化平台（''/vmware/hyperv/kvm/proxmox/xen/virtualbox/parallels/other）；
- `devices.is_virtual_host`：是否虚拟化宿主机。

### 4. 服务器连接核对报表

入口：拓扑管理 → 服务器连接核对（`/topology/server_link_verify`）。

每行列出：服务器名称、管理 IP、BMC IP、BMC MAC、虚拟化类型、是否宿主机、
物理网卡 MAC（排除 VM OUI）、对端交换机、交换机端口、发现协议（LLDP/SNMP MAC/IPMAC）、
链路状态。支持关键字过滤与 CSV 导出，用于“交换机端口 ↔ 宿主机物理网卡 MAC ↔ BMC ↔ 管理 IP”
的人工交叉核对。

## 四、注意事项

1. VM OUI 是启发式规则：若虚拟机启用了 MAC 随机化（如 Windows 随机 MAC 02:xx），可能漏判，
   建议以 LLDP 为主、OUI 为兜底。
2. LLDP 能力位是区分“级联交换机”与“宿主机”最可靠的字段；BPDU 检测需要镜像端口抓包，
   不适合 SNMP 采集，故未实现，用能力位 + OUI 组合替代。
3. 宿主机物理网卡做 LACP 聚合时，交换机会在多个成员口分别学到物理网卡 MAC，
   系统按端口分别建链，核对报表可看到聚合成员对应关系。
